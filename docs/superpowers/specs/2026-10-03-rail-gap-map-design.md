# 設計書: 鉄道空白地帯の可視化 (rail-gap-map)

- 作成日: 2026-10-03
- 状態: 計算の土台として実装済み。画面と表し方は [v2 (空白地帯を主役にする)](2026-10-03-gap-first-redesign.md) で置き換えた

## 1. 目的

「最寄り駅まで歩いて何分か」を**等距離線 (徒歩 5・10・15・20・25・30・45・60 分)** で地図に描き、駅から遠い所 (鉄道の空白地帯) を見せる。個人ブログで発表する単発の静的 Web アプリとする。

- 代表例: 練馬区 大泉学園町。都営大江戸線の延伸 (光が丘〜大泉学園町) の予定駅を加えた「延伸前 / 延伸後」を比べられるようにする。
- 見る人が**自分の住む場所を探せる**ようにする (町丁目・駅名の検索と現在地。どちらもブラウザの外へ位置を送らない)。
- まず東京。設定ファイルを足せば他の主要都市へ広げられる作りにする。

## 2. 決定事項

| 項目 | 決定 |

| 表示範囲 | 東京都の島しょを除く部分 (23区+多摩) |
| 計算範囲 | 表示範囲の外側 3 km まで (隣県の駅・道路も含める) |

| 徒歩速度 | 80 m/分で一定 |
| 延伸シナリオ | 最初は大江戸線延伸のみ。他の計画は設定ファイルを足せば加えられる形 |

| 配るデータ | 都市・シナリオごとの GeoJSON。重すぎた場合だけ PMTiles を検討する |

## 3. データ源

使う前に `docs/sources/<名前>.md` に、正式名称・提供者・URL・ライセンス・出典表記・版・取得日時 (UTC)・SHA-256 を記録する。**ダウンロードは毎回、ファイル名・取得元・大きさを示して利用者の確認を取ってから行う。** 生データはコミットしない。

| 用途 | データ | 版 (予定) | ライセンス / 出典表記 |
|---|---|---|---|
| 道路網・水域 | OSM 関東抽出 (Geofabrik) | 2026 年の月次版から 1 つを固定 (約 490 MB。ファイル名は取得時に確認する) | ODbL 1.0。「© OpenStreetMap contributors」 |
| 駅 | 国土数値情報 鉄道データ N02-25 (`N02-25_GML.zip`、14.2 MB) | 基準日 2025-12-31 | CC BY 4.0。「『国土数値情報（鉄道データ）』（国土交通省）をもとに作成」 |
| 範囲・陸地・区市町村界 | 国土数値情報 行政区域 N03 (東京都・埼玉県・神奈川県・千葉県) | 最新版 (取得時に確認する) | CC BY 4.0 |
| 町丁目の検索 | アドレス・ベース・レジストリ 町字マスター位置参照拡張 (東京都、デジタル庁) | 取得時に確認する | CC BY 4.0 (取得時に再確認する) |
| 背景地図 | 地理院タイル 淡色地図 (raster、リアルタイム読み込み) | — | 「地理院タイル」+ タイル一覧ページへのリンク |
| 延伸予定駅 | 東京都 都市整備局「大江戸線延伸の検討状況」(2025-10-15) の概略図、練馬区の延伸ページ | — | 出典 URL を書き、位置は「概略図から筆者が推定」と明記する |

調べて分かった事実:

- N02 の駅は点ではなく「路線の一部分 (ホーム区間の線)」として収められている。
- 大江戸線延伸 (約 4 km) は都の資料で「事業性の検証」の段階にあり、開業は 2040 年頃の想定。予定駅 (仮称) は土支田・大泉町・大泉学園町の 3 駅。**座標は公表されていない**。資料には「土支田通りの東側」「外環道との交差部西側」「大泉学園通りとの交差部東側」という説明と概略図があるだけ。駅名と位置の対応も推定になる。
- 国土地理院の住所検索 API は正式な利用規約が無く、実体は実験サービスである。Nominatim は 1 秒 1 回の制限と入力補完の禁止がある。いずれも使わず、町丁目の代表点データを静的ファイルにしてブラウザ内で検索する。

### 2 つ目のアプリとの共通部分

多始点ダイクストラの結果「道路の点ごとの道のり + 最寄り駅 ID」(`data/build/<region>/solve-<scenario>.parquet`) と、最寄り駅 ID を持つ格子を共通の中間成果物とする。「どの駅の徒歩圏に入るか」アプリはこれを使う。同じリポジトリの別ページにするか、別リポジトリから `ekiwalk` を `uv add git+...` で使うかは、そのアプリを作るときに決める。

## 5. データ作成の流れ (Python)

各段階は `data/build/<region>/` に Parquet / NPZ を書き、次の段階はそれを読む。段階ごとに作り直せる。

1. **network**: DuckDB spatial (`ST_ReadOSM`) で PBF を読む。計算範囲内の歩ける way を線にし、交差点で区切ったグラフにする。距離は平面直角座標系 IX 系 (EPSG:6677) で測る。DuckDB で読めない場合は pyosmium に切り替える。
   - 除く道: `highway=motorway/motorway_link`、`motorroad=yes`、`foot=no`、`access=no/private` (ただし `foot=yes/designated` があれば歩ける扱い)、`highway=construction/proposed`
   - 含める道: それ以外の `highway=*` (歩道・階段・小道・生活道路・一般道路)
   - 水域ポリゴン (`natural=water`、`waterway=riverbank` など) も同時に取り出す
   - 最大の連結成分だけを残す。孤立した小さな部分は捨て、捨てた数を記録する
2. **stations**: N02-25 の駅の線を読み、計算範囲で切り出す。乗換駅は表示用に、駅名と近さ (例: 300 m 以内) でまとめる。シナリオの予定駅は点として足す。
3. **solve**: 駅の線 (予定駅は点) から 100 m 以内にあるグラフの点を、すべて出発点にする。駅からの直線距離を初期値として `scipy.sparse.csgraph.dijkstra(..., min_only=True, return_predecessors=True)` を 1 回実行し、道のり (m) と最寄り駅 ID を得る。100 m 以内に点が無い駅は、最も近い点を出発点にして記録する。
4. **surface**:
   - 辺に沿って約 20 m ごとに点を打つ。各点の道のりは辺の両端から線形に求める (`min(dA + s, dB + L − s)`)
   - 25 m 格子の各マスに「半径 300 m 以内の近い点 (k = 8) の、道のり + 直線距離」の最小値を入れる
   - 次のマスは空白 (NaN) にする: 近くの点が 300 m 以内に無いマス、水域、N03 の陸地の外 (海)
   - 最寄り駅 ID も同じ方法で格子に入れる
5. **contours**:
   - 格子を少しぼかす (ガウス σ = 1 マス。空白を広げない扱いにする)
   - `contourpy` で等値線 (線) と帯 (塗り) を作る。段階は 5・10・15・20・25・30・45・60 分 (400〜4800 m)。60 分より遠い所は「60 分以上」の帯にする
   - 約 5 m で単純化し、表示範囲 (東京都の島しょを除く部分) で切り抜いて、WGS84・小数 5 桁で書き出す
   - 差分は「延伸前の格子 − 延伸後の格子 ≥ 400 m (5 分)」の範囲をポリゴンにする
   - 最寄り駅 ID の格子から「最寄り駅の範囲」ポリゴンを作り、クリック時の表示に使う
6. **places**: 町丁目の代表点 (ABR) と駅名から、検索用の JSON (`名前, よみ, 区市町村, 経度, 緯度`) を作る。
7. **export-web**: `web/data/<region>/` に次のファイルを書く。
   - `bands-<scenario>.geojson`、`lines-<scenario>.geojson`、`diff-<scenario>.geojson`、`catchments-<scenario>.geojson`
   - `stations.geojson`、`places.json`、`boundaries.geojson` (区市町村界)、`meta.json` (データの版・作成日・出典)

## 6. 画面

- **全画面の地図** (背景は地理院タイル 淡色地図)
  - 帯は遠いほど濃い色にし、空白が目立つようにする。線は細く、線に沿って「10分」などのラベルを付ける
  - 区市町村界を細い線で描く
  - 駅は点で描き、拡大すると駅名を出す。予定駅は点線の丸と「(仮称)・概略位置」で描く
- **自分の場所を探す** (左上)
  - 検索欄: 町丁目 (例「大泉学園町6丁目」) または駅名を入れると、候補から選んでその場所へ移る。検索はブラウザ内の `places.json` だけで行い、入力した文字をどこにも送らない
  - 「現在地」ボタン: ブラウザの位置情報を使う。位置はブラウザの中だけで使い、送らず、保存もしない
  - 移った先に印を付け、その地点の情報を表示する
  - 地図の中心位置を URL に入れない (共有したときに住む場所が漏れないように)
- **地点の情報** (クリック・検索・現在地のとき): 「最寄り駅: ○○駅 / 徒歩 15〜20 分の帯」。延伸後の表示中は「延伸前 15〜20 分 → 延伸後 5〜10 分」と出す。
- **右上**: `延伸前 | 延伸後` の切り替え。延伸後のとき「5 分以上近くなった所」を斜線で示す。
- **「大泉学園町へ」ボタン**: ブログで説明するための視点へ移る。
- **下部の折りたたみ**: 「この地図の限界」と「出典」。限界として書くこと:
  - 駅の位置はホームの中心線で、出口ではない
  - 道のりは 80 m/分で一定。信号・坂・階段・混雑は入れていない
  - バスは考えていない
  - OSM に載っていない道・通れない私道の扱いはデータ次第である
  - 道から離れた所は直線で歩くと仮定した
  - 予定駅は概略図から推定した位置で、開業時期も未定
  - 各データの基準日
- スマホ幅 (16 px の余白、横スクロール無し) にも対応する。
- 地理院タイルを読み込むと、表示している範囲のタイル要求は国土地理院のサーバーに届く。この点を出典欄に注記する。

## 7. 失敗時の扱い

- データ作成の各段階は、入力が無い・版が設定と違う・件数が極端に少ないときに止まり、何が足りないかを表示する。
- 画面は、データが読めないときに地図の上へ短いエラーを出す。位置情報が拒否されたときは検索を勧める。

## 8. 検証

- **単体テスト (pytest)**:
  - 小さな人工グラフで、道のり・最寄り駅・辺の上の補間を確かめる
  - 歩けない道の判定 (タグの組み合わせ) を確かめる
  - 中心から放射状に増える距離の場で、等値線の半径が段階の値と合うかを確かめる
  - 空白 (水域・道から遠い所) が等値線に入らないことを確かめる
- **小さな範囲での試運転**: 大泉学園町を中心とする約 4 km 四方で全段階を通す。ブラウザで線の形を見る。
- **実データでの確認**: 次のことを数値と地図で確かめる。
  - 駅のすぐそばが 0〜2 分になっている
  - 大泉学園町付近が延伸前に 20 分以上、延伸後に短くなっている
  - 川を挟んだ所で、橋まで回る分だけ遠くなっている
- **画面**: 検索・現在地 (拒否を含む)・切り替え・スマホ幅を、アプリ内のブラウザで確認する。
